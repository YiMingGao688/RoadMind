# RoadMind 分阶段开发计划

每个阶段先确认输入和业务边界，再实现、验证和更新文档；不以目录或依赖存在作为功能已经完成的依据。

## 第一阶段：基础后端（已完成）

- Java 21、Spring Boot 4.1.2、Maven 的单工程结构。
- 统一 API 响应、异常处理、Jakarta Validation 和开发环境配置。
- 业务健康接口与 Actuator 最小健康端点。
- 健康检查及常见错误处理测试、依赖解析、可执行 JAR 与 HTTP 启动验证。
- Spring AI 2.0.2 BOM 与 MyBatis-Plus 3.5.17 Boot 4 starter 版本管理。

验收：不依赖数据库、缓存或模型服务即可构建、启动，`GET /api/health` 返回 HTTP 200 和 UP。实际命令及结果见 [验证记录](verification.md)。第一阶段结束时前端目录为空。

## 第二阶段：六页面 AI 应用前端（已完成演示范围）

- 保留 Vue 3、TypeScript、Vite、Element Plus、Vue Router、Pinia、Axios 与 SCSS。
- 按已确定的参考图实现 AI 助手首页、对话与引用、知识探索、养护助手、我的知识库、RAG 实验室。
- 共享 AI 侧栏、输入框、消息、引用、文档预览与照片卡片，使用统一设计 Token、本地字体和 SVG 图标。
- 保留本地创建、文件校验/登记；实现会话切换/中断/原位重试、资料片段定位和参数快照等演示流程。
- 通过类型检查、生产构建与 17 项浏览器回归，在两种桌面尺寸完成实际截图复核。

验收：所有业务 Mock 均明确标识，未连接模型、真实上传或向量库。没有改动 Java 后端或自动提交 Git。详情见[六页交付验证](frontend-six-page-verification.md)。
## 第三阶段：MySQL 与知识库元数据（已完成）

- 启用 MyBatis-Plus 3.5.17 Boot 4 Starter、MySQL Connector/J 与 Flyway。
- 通过 V1 迁移建立 utf8mb4 知识库主表、合理索引与有效名称唯一约束。
- 实现创建、分页/分类/名称查询、详情、修改与逻辑删除，保持统一响应与校验。
- 我的知识库接入真实 Axios API，支持编辑、删除确认、错误重试、空状态和服务端分页。
- 保留独立 Mock 模式；真实文档数为 0，不混入演示文档和统计。
- 原有 13 项与新增 10 项 Maven 测试通过；17 项演示及 7 项真实 API 浏览器测试通过。
- 测试使用独立 roadmind_test，并验证刷新和测试后端重启后记录仍在 MySQL。

验收与证据见[第三阶段验证](phase3-verification.md)，表结构及 API 见[接口设计](knowledge-base-api.md)。没有接入模型、Milvus、Redis 或 MinIO，没有自动提交 Git。
## 第四阶段：文档管理与入库流水线

- 接入 MinIO，提供文件类型、大小及访问权限校验。
- 根据真实样本文档选择 PDF / Word 解析组件，保留页码等来源定位信息。
- 实现切片、入库状态与失败原因记录，明确任务重试及幂等规则。
- 仅在异步任务规模与失败恢复需要时引入 RabbitMQ；Redis 同样按实际需求加入。

验收：使用可授权的规范、养护手册和应急预案样本验证解析结果、状态转换和失败恢复。

## 第五阶段：基础 RAG

- 依据 Spring AI 2.0.2 官方 API 接入选定模型和 Embedding，不引入旧版 API 或 Spring AI Alibaba。
- 接入 Milvus，确定向量维度、元数据字段与索引策略。
- 完成查询向量化、相关片段检索、上下文构建和答案来源引用。
- 对无命中、模型失败和知识不足给出明确结果，避免伪造依据。

验收：答案引用能定位至真实文档和片段，记录基础检索与问答评估结果。

## 第六阶段：Advanced RAG 与调试

- 以评估结果为依据加入混合检索和 Rerank。
- 提供检索调试接口及前端界面，展示候选片段、排序分数与引用来源。
- 评估检索命中、回答依据、耗时和成本，并保留可复现的评估数据。

验收：同一测试集可比较优化前后的质量和耗时，不仅展示最终回答。

## 第七阶段：Agent 交通业务查询

- 定义病害、交通事件和巡检设备的工具输入、输出及数据来源。
- 封装经过参数与权限校验的只读业务查询，通过 Spring AI Tool Calling 编排。
- 加入执行次数、超时、失败处理与调用记录，限制工具使用范围。
- 演示数据和真实业务接口明确区分；实际外部调用前确认接口契约和授权。

验收：工具调用结果可追溯至实际数据或明确标记的演示数据，工具失败不伪装为成功。

## 第八阶段：权限、前端完善与部署

- 在对外部署前完成 Spring Security、登录鉴权、资源访问控制和必要审计。
- 前端采用 Vue 3、TypeScript、Vite、Element Plus、Axios、Pinia，逐步完成知识库、问答、检索调试页面。
- 提供 Docker / Docker Compose、Nginx 和 Linux 部署文档，配置与密钥通过环境变量注入。
- 完成端到端验证、异常场景、性能与运维检查。

验收：具备可重复部署与验证的应用；企业生产上线另行完成相应的业务、数据与运行验收。
